## Commands

```bash
npm run dev       # start dev server (Vite, hot reload)
npm run build     # production build → dist/
npm run preview   # serve the dist/ build locally
```

No test runner or linter is configured.

## Project overview

**Aria Bene Comune** — a civic air-quality monitoring dashboard for Taranto, Italy. All sensor data is static/simulated (noted in the UI footer). The app is bilingual (Italian / English), switching via a `lang` state string (`'it'` | `'en'`).

## Architecture

### Routing

There is no router library. Navigation is managed by a `page` state string in `App.jsx` (`'home' | 'map' | 'archive' | 'record' | 'symptoms'`). Pages are conditionally rendered with `{page === 'x' && <XPage ... />}`. The `TopBar` logo and `MobileNav` navigate to `'home'`; the `TopBar` nav links cover `map`, `archive`, and `symptoms` only — `'home'` is not in the nav list.

### Data layer (`src/data/`)

**Single source of truth: `mock_data.csv`** — 1,344 rows (8 sensors × 7 days × 24 hours), generated by `scripts/generate_mock_data.mjs`. To regenerate: `node scripts/generate_mock_data.mjs`.

- `mock_data.csv` — columns: `ts,sensor_id,pm25,pm10,no2,o3,so2,co,nh3,c6h6,temp,hum`. Imported with Vite's `?raw` suffix and parsed synchronously at module load.
- `sensor_meta.js` — spatial/display metadata only (id, name, location, district, x, y). No readings.
- `loader.js` — parses CSV + merges with `sensor_meta.js` → exports `SENSORS` (metadata + latest reading per sensor) and `HOURLY_DATA` (all rows, sorted). This is the only place numbers are parsed.
- `sensors.js` — thin re-export: `export { SENSORS } from './loader'`
- `timeseries.js` — thin re-export: `export { HOURLY_DATA } from './loader'`
- `pollutants.js` — `POLLUTANTS` map defining name, unit, category (`particulates | gaseous | systemic`), and 6-level threshold `ranges` for each of the 8 pollutants
- `levels.js` — `LEVELS` array of 6 AQI quality levels (index 0–5) with Italian/English labels and hex colors
- `symptoms.js` — `SYMPTOMS` and `SUGGESTIONS` keyed by pollutant category and AQI level key

All "current" sensor readings (home cards, map, record header) = latest row per sensor in the CSV. All sparklines and heatmaps pull from `HOURLY_DATA` — nothing generates its own numbers.

### AQI calculation (`src/utils/aqi.js`)

- `getPollLevel(key, val)` — maps a pollutant value to an index 0–5 using the ranges in `POLLUTANTS`. Uses upper-bound-only comparison (`val <= range[1]`) so values in decimal gaps between declared ranges don't jump to the worst level.
- `getSensorAQI(sensor)` — returns the worst (max) level index across all 8 pollutants for a sensor

### Theming

Dark mode is implemented by overriding four CSS custom properties (`--black`, `--white`, `--gray`, `--gray2`) at the `documentElement` level in `App.jsx`. Font scale is similarly applied directly to `document.documentElement.style.fontSize`.

CSS variables are defined in `src/index.css` (`:root`). The two typefaces used throughout are:
- `var(--font-title)` → `'Epilogue'` (sans-serif) — headings, labels, UI chrome
- `var(--font-body)` → `'Source Serif 4'` (serif) — body text, data values

### TweaksPanel (`src/components/tweaks/`)

A floating dev-only overlay for toggling dark mode, font scale, and language. It listens for `window.postMessage` events (`__activate_edit_mode` / `__deactivate_edit_mode`) so it can be controlled by a parent frame. The `useTweaks` hook persists tweak values.

### Maps

Both `MapPage` and the mini-map in `RecordPage` are hand-drawn SVG paths — there is no mapping library. Sensor positions are stored as fractions (`s.x`, `s.y`) and scaled to the SVG viewport at render time.

### HeroDots component

`src/components/HeroDots.jsx` renders an animated dot-grid decoration keyed to the current AQI level index. It is used in both `HomePage` (hero area) and `SymptomsPage` (figure column).

### Public assets (`public/assets/`)

SVG files for the body figure used in `SymptomsPage`: `corpo.svg` (full body silhouette), plus per-organ files `mind.svg`, `eyes.svg`, `throat.svg`, `lungs.svg`, `stomach.svg`. Each organ file is applied as a CSS mask over a colored `<span>`, so organ color is set entirely through `background-color` on the masked element.

### Page-specific notes

- **RecordPage** requires a `sensor` prop; if falsy it renders a placeholder. Navigation to it must also call `setSelectedSensor(s)` before `setPage('record')`. The pollutants grid is now interactive: clicking a cell sets `activePollutant` state, which updates both the 24-hour sparkline and the heatmap to display that pollutant. The grid appears above the chart.
- **ArchivePage** filters `HOURLY_DATA` client-side with `useMemo`; `fDateFrom` / `fDateTo` default to `2026-04-30` – `2026-05-07` (the CSV coverage window).
- **ReportPage** is a client-side-only symptom report form (name, neighbourhood, symptoms checkboxes, note). Submitted reports are stored in component state (not persisted) and shown as the last 10 entries. No backend.
- **SymptomsPage** no longer uses the static `SENSORS` snapshot for AQI. It derives per-category levels from `HOURLY_DATA` scoped to the latest hour, optionally filtered by a neighborhood (`activeDistrict`). Each body zone is colored independently by its linked pollutant category's current level (`zoneColors`). The `BodyFigure` component uses `corpo.svg` as the base image with organ SVGs applied as CSS-masked overlays positioned via percentage `top`/`left` in `ORGAN_LAYOUT`.
